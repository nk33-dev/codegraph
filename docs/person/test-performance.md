# 测试性能

## 本地实现

本轮基于已发布的 `4477e92`，改动只保留在本地，尚未推送或发布。

- 调用 Git 查询 HEAD、变化列表或可见文件前，以文件系统检查项目及祖先的 `.git`。明确不在仓库中的目录直接使用已有非 Git 路径，避免重复启动必然失败的子进程。判定不缓存，后续 `git init` 立即生效；worktree 指针、bare 仓库、环境指定仓库及不可确认的文件系统状态继续交给 Git 判定。
- 全局 `core.excludesFile` 仍按原规则查询，Git 仓库的 status、提交差异和文件清单不缓存。不能用减少命令的方式声称工作区干净。
- `check:quick` 与 `test:focused` 只执行 engine/ui。engine 与 perf 共享的测试文件在普通检查只运行一次；`test:perf` 保持串行和严格计时断言。
- 受影响测试选择每个测试文件只读取、解析一次；直接导入和领域规则保持不变。共享入口变化可能仍会选中大量测试，不以缩小覆盖范围制造加速。

## Windows 本机测量

Node v24.16.0，同一天、同机器、同源码样本；测量脚本在临时目录，不进入发布包。

仅一个 TypeScript 文件、非 Git 临时项目，连续三次建索引后做无变更同步：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Git 调用数 | 17 | 4 |
| Git 累计耗时 | 1,051～1,087 ms | 259～281 ms |
| 建索引 | 684～775 ms | 391～451 ms |
| 无变更同步 | 626～682 ms | 216～270 ms |

Git 调用的剩余成本是全局 ignore 配置读取；正文提取本身只有毫秒级成本。数据只覆盖此小样本，不代表所有 Git 仓库或 CI 的相同比例收益。

七个变更文件的测试选择从约 562 ms 降到 173 ms，优化前后均选中 277 个文件，逐行结果相同。这是单次测量，不作为严格延迟门禁。

## 验证与范围

新增回归覆盖非 Git 项目的实际索引/同步、探测后 git init、仓库子目录、worktree 指针、bare 仓库、GIT_DIR 和受影响测试项目选择。提交/restore/失败回退与 ignore 配置相关的五文件 `check:quick` 通过类型检查及 44 项测试。

已发布 .13 的 Windows CI 作业耗时 30 分 4 秒，Linux 5 分 55 秒，macOS 3 分 50 秒；这些是优化前的发行记录。未推送本地优化，不能称三平台性能已验证。同步/解析两文件 286 项通过；基线有一项超时，文件耗时从约 171/197 秒降到 102/77 秒，不能视为严格 CI 对照。完整复测与清理恢复事实见[开发验证记录](test-repairs.md)。
