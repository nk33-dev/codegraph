# CodeGraph v1.6.2-personal.1

**状态：已发布（2026-10-04）。** 标签 `v1.6.2-personal.1` 指向 `700d31d9`，同提交三平台 CI `37178187510` 与 `Personal Release` `37178636930` 均成功，资产为 `colbymchenry-codegraph-1.6.2-personal.1.tgz`（9,179,895 字节，SHA-256 `2383c4af2a845c0301a625dddb80cd19cc4cab989d74e02613c1bdba58553d32`）与 `SHA256SUMS`。安装命令如下文。

上游 v1.6.2 同步之后的第一个个人版本。LSP 侧把项目配置、诊断、补全与格式化接进同一套事务管线并复用文件读取；索引侧补齐风险热点、Rust 构建上下文、索引期读缓存与写入窗口字节预算；另有依赖边界检查、端到端图基线和按符号快照决定的局部刷新。

### Highlights

- **LSP 按工作区应答配置。** `.codegraph/lsp.json` 新增 `settings`，`workspace/configuration` 逐项判断 `scopeUri` 是否落在本项目内，再按 `section`（字面量键优先，否则按 `.` 逐级）取值；客户端能力里的 `workspace.configuration` 由 `false` 改为 `true`。没有 `settings` 时行为与之前等价，仍返回 `null` 数组。rust-analyzer 的 `check`、pyright 的分析选项这类依赖该反向请求的服务，此前拿不到任何项目配置。
- **pull 诊断与 push 诊断分开存储后合并。** `textDocument/diagnostic` 请求携带 `previousResultId`，响应里的 `resultId` 被保留，`kind: "unchanged"` 复用上次结果；两种来源按位置/严重度/代码/来源/消息去重后合并，`-32802`（ServerCancelled）重试一次。此前 pull 是 push 的降级路径，一种来源会整批覆盖另一种。
- **补全与整文件格式化进入现有 MCP 入口。** `codegraph_explore` 新增 `completion` 模式：按 `sortText`（缺失时用 `label`）排序并分页，服务器支持 `completionItem/resolve` 时补齐 `detail`/`documentation`，单条解析失败只标记该条。`codegraph_edit` 新增 `operation:"format"`：向服务器请求 `textDocument/formatting`，返回的文本修改走与重命名、正文替换同一条预览与事务写入路径，`tabSize`/`insertSpaces` 可显式指定。两者都不新增工具，默认 MCP 表面仍是 `codegraph_explore` 与 `codegraph_edit`。
- **文件文本只读一次。** LSP 的定位与文档同步共用按 mtime + size 复核的进程内文本缓存，语言服务器停止即清空、文件变化即失效。同一文件反复查询、大文件与多窗口场景收益最明显；此前每个 `textDocument/*` 请求都重新读盘。
- **局部刷新范围按符号快照决定。** 不再看文件里有没有 `interface`/`export`/`route` 关键字：比较索引快照与当前文本的符号，只有函数体变化时收敛到该文件，导出符号增删、`kind`、声明签名或 import/export 表面变化时才带上已解析出的依赖者。
- **依赖边界与模块环检查（`codegraph architecture`）。** 规则写在 `codegraph.json` 的 `architecture.boundaries.deny`，违规报告带 `file:line`、边类型和声明/推断标记；`--strict` 在有违规时退出 1，用于 CI 门禁。模块划分与查看器地图共用 `src/graph/module-map.ts`，范围默认由 `pickDefaultView` 选取（报告里以 `autoScope` 标注）。
- **风险热点排序（`codegraph hotspots`）。** 按 `复杂度 × (1 + 调用方数) × 改动加权 × 测试折减` 排序最该先读的函数；`--base <ref>` 传入改动符号，`--strict` 在有符号达到阈值时退出 1，阈值、条数、文件上限与两个权重可在 `codegraph.json` 的 `hotspots` 块里改。复杂度是决策点计数，**读时现算不落库**；调用方数按调用方符号去重（一个调用方调两次只记一次）；`gated` 在所有被评分符号上统计，被 `maxItems` 截掉的符号照样能让 CI 失败。`codegraph_hotspots` MCP 工具与 CLI 同源，同样不进默认表面。
- **Rust 符号带构建上下文。** `codegraph node` 与 `codegraph_node` 对 Rust 符号多输出一行：文件属于哪个 crate、是不是 workspace 成员、该 crate 声明了哪些 feature 与依赖。manifest 读取与 workspace 解析器共用 `src/cargo-manifest.ts`，所以解析出的 crate 名与这里报的不会不一致；查询期现算，不落库、不加边。catalog 的缓存复核除每个 manifest 的 mtime + size 外，还比较 `crates/*` 这类 glob member 当前的展开结果，所以往 glob 下新增 crate 无需重启进程；`default-members` 不会被当成成员表。
- **索引与解析的重复读取改为按变更戳缓存，写入窗口叠加字节预算。** 文件清单、节点名清单、语言清单、框架探测与逐 ref 的框架循环不再每轮重跑 SQL/重扫磁盘；缓存按 `total_changes()` + `data_version` 失效（覆盖其它连接与 daemon 的提交），事务内不缓存，`rebind()` 清空，返回值冻结。存储写入线程在条数窗口之外新增字节预算（`CODEGRAPH_STORE_WINDOW_MB`，档位 48/96/192MB），密集源码不再因为「64 个 bundle」而与体积无关地尖峰。
- **同步按需重新检测框架。** 检测结果此前只在全量索引时重算，于是同步进来的第一门语言的文件、或新出现的 `requirements.txt` 这类 manifest，会以「没有框架」的状态解析，直到下一次全量索引。现在同步先判断变更集是否可能影响检测——有文件新增或移除，或改动路径正是上次检测读过的 manifest——命中时引用解析器与提取编排器都重算，纯函数体编辑不重扫。
- **修上游 v1.6.2 同步留下的解析语义冲突。** 这批失败在纯上游 v1.6.2 上不存在，是个人侧改动与上游新逻辑互斥：个人「未知属性链」的早退挡在命名空间分支之前，`z.core.safeParse()` 这类以 `import * as` 为根的链永远解析不到（上游 #2192 失效）；`calls` 坐标锚点改到成员标识符后，上游按列回读调用点判断接收者的逻辑读不到接收者，Python `self.get_ip()` 被同名导入截胡（#2125）、JS 自调用与「另一个表达式上的同名调用不算本方法的调用方」判定回退（#2223）；增量同步的预删被放在重存事务之外，存储阶段失败会把旧节点与入边一起提交删除（#2276）。坐标冲突的处理办法见[维护流程](../maintenance.md)。
- **端到端图基线。** 索引一份刻意包含反例的 6 文件 fixture，整图与提交进仓库的 golden 逐行比对，并附具名不变量（同名方法解析到正确的类、未知 receiver 进 `unresolved_refs` 而不伪造边、删除文件后同步无残留）。
- 测试性能：减少测试中的 Git 调用，Windows CI 分到三台 runner 分片。实现与测量见[测试性能](../test-performance.md)。

### Installation

推荐 Node.js 24；从源码运行需要 Node.js 22.5 及以上（SQLite 使用 `node:sqlite`）。

```powershell
npm install -g "https://github.com/nk33-dev/codegraph/releases/download/v1.6.2-personal.1/colbymchenry-codegraph-1.6.2-personal.1.tgz"
codegraph doctor --json
codegraph install --refresh
```

schema 与提取版本与 v1.6.0-personal.13 相同，无需升级索引。安装后完整退出并重新打开 MCP 客户端。

### Known limitations

- **诊断合并可能短暂陈旧**：文件变更后 pull 表不立即失效，合并结果可能短时间内仍显示旧的 pull 项。按参考实现保留。
- **自动范围会漂移**：`architecture` 与 `hotspots` 未显式配置范围时随仓库结构变化；CI 门禁应显式写 `root`（写 `""` 表示整个仓库），否则新的顶层目录可能改变被检查的模块或文件集合。
- **模块环含裸名称匹配的边**（与查看器地图一致，不受 `requireDeclared` 约束），在内部互相引用的单体 `src/` 上会缩成一个横跨十余个模块的环。
- **热点是启发式排序**：复杂度是决策点计数，不是循环复杂度；调用方数来自图，缺边处会低估；`--base` 只按 Git 改动取符号，不判断改动是否真的进入制品。
- **Rust 构建上下文是声明清单，不是构建图**：不调用 `cargo metadata`，`features` 是 crate 声明的键而不是某次构建启用的集合，`#[cfg(...)]` 未被提取，依赖包含 dev/build/optional，`[target.'cfg(...)'.dependencies]` 与 `[workspace.dependencies]` 会被跳过而不是半解析。
- **索引期读缓存的前提**：缓存按数据库变更戳失效，事务内不缓存；单进程外的改动（含 daemon）依赖 `PRAGMA data_version`。返回值已冻结，调用方不得改写。
- **写入窗口字节预算是「与」条数窗口叠加的**，只在平均 bundle 超过 `storeWindowMb × 1024 / 64`（balanced 约 1.5 MiB）时先满足；小文件仓调度与之前一致。
- **图基线对行号敏感**：改动 fixture 必须用 `CODEGRAPH_UPDATE_GRAPH_GOLDEN=1` 重生成 golden 并 review diff。
- 计算路由、动态组件、spread props、内联回调、反射、运行时注册与事件名仍可能缺边；推断关系不能代替编译器或运行时验证。
