# 个人版生产硬化与发布准备

阶段六的可审查提交链、仓库自动化、本地产物验证、常规三平台 CI 和 GitHub prerelease 已纳入本轮交付；Hardening 中的真实 LSP、原生 kernel、长时间恢复/并发场景，以及真实仓库 Agent A/B 仍必须在实际运行后再记录，不能把工作流配置当成通过结果。

## 已实现

- 常规 CI 在 Windows、Ubuntu、macOS 执行 `npm ci`、build 和全量测试。
- `Hardening` 夜间/手动工作流验证三平台安装包、三平台原生 kernel、真实 TypeScript/Python LSP，以及 daemon/事务恢复和并发客户端。
- `Personal Release` 手动工作流验证并上传个人 `.tgz` 与 `SHA256SUMS`，创建或刷新个人 GitHub prerelease，不写回分支、不发布 npm。
- 上游 `Release` 工作流增加仓库身份保护，在 `nk33-dev/codegraph` 不运行上游标签、PAT、npm scope 和 `main` 写回流程。
- 根包元数据指向 `nk33-dev/codegraph`，并设置 `private: true`，防止把根包误发到 registry。版本号和包名未擅自修改。
- 安装产物验证覆盖 doctor、构建指纹、UI/WASM 资源、Graph 查询、编辑预览、事务 apply 和相同 operation ID 重放。

## 评测记录要求

真实仓库评测继续使用 `docs/validation.md` 的小、中、大仓库方法和
`scripts/agent-eval/ab-new-vs-baseline.sh`。每个问题至少每臂两次，记录 duration、Read、Grep、工具调用、输出利用率、错误边、索引时间、内存和数据库大小。结果必须包含：

- 个人构建的 build ID、提交、dirty 状态、Node/平台；
- 仓库提交与规模，问题原文和两臂使用的同一模型；
- 每次运行而不是只有均值，并标明 CLI 污染检查；
- 未安装 LSP、跳过 kernel、共享 runner 抖动等限制。

当前没有在本工作区内伪造这些数字。`v1.6.0-personal.1` 的三平台运行 `35126540607` 构建均通过，但测试暴露了 Windows 短路径、macOS `/var` 路径、跨平台 URI 断言和事务测试注入问题。`v1.6.0-personal.2` 的运行 `35131681211` 又暴露两处修复方式错误：macOS 输入路径被错误 canonicalize，跨卷注入仍依赖路径拼写；Python fixture 同时配置 TypeScript，导致“复用 Python 服务”测试观察到第二个服务进程。因此 `personal.2` 不能记为三平台通过，后续修复也不代表真实仓库 Agent A/B、能耗测量或 npm registry 发布已经完成。

修复后的行为基线 `f0fc59b` 在运行 `35185598909` 中通过 Windows、Ubuntu 和 macOS 的 build 与全量测试。`v1.6.0-personal.3` 只在该三平台结果之后更新版本和发行资料，并继续通过 GitHub `.tgz` 交付，不发布 npm registry。

发行提交 `f4a22e6` 的运行 `35190011391` 在 Windows 上出现索引超时，随后清理 SQLite 失败、指标串扰。此前临时把 Windows 降到单 worker；日志没有 CPU、内存与分阶段数据，不能据此认定根因就是四并发过量。2026-09-17 进一步修复了测试索引任务的取消与等待、初始化失败的连接释放，以及数据库维护线程未等退出就返回的问题，并恢复四并发。证据与验证边界见[开发验证记录](test-repairs.md#2026-09-17windows-四并发与资源清理)。

个人功能已按核心运行能力、测试与平台稳定性、发行基础设施、文档和发布记录形成可独立审查的提交链；发布说明覆盖结构化查询、LSP、共享 daemon、事务编辑、资源治理、稳定性和安装交付，不只罗列六阶段计划。

本轮在已有补丁上修复的实际问题：

- `includeIndirect` 在统一路由投影时丢失，导致 CLI explore / MCP 无法展开间接候选；现已透传并在投影前校验。
- 关联测试首次到达即去重，会让公共模块路径遮住较强路径；现分别遍历两类路径，距离与前驱跟随所选置信度。
- 按行列重命名绕过完整性检查，同一行只改一个引用也可能被判为全部覆盖；现先解析定义，再比较具体范围，陈旧引用拒绝使用。
- 精确单符号查询仍使用模糊种子，测试还可能被排名或分配预算淘汰；现复用单跳图遍历，保留用户所需的直接引用文件和调用现场，不用名称相似性补造调用边。
- 普通源码查询只要碰到一个改动文件就附带全工作区变更；现限制为该次查询候选文件，显式改动审查仍保持完整范围。
- 回滚可能用旧备份覆盖外部修改，或删除事务未创建的目标；现提交前复核并保留冲突现场，必要时返回 `recovery_required`。事务内部 `EEXIST` 不再触发整笔操作重试，刚创建的空锁也不会被立即抢占。
- 配置未变化时缺少重启提醒、升级只验版本不验入口、环境变量固定版本行为不一致；现安装/刷新均提示，升级核对 npm 全局目录及 doctor 返回的发行身份和包路径。
